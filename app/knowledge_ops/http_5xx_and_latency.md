# HTTP 5xx 与接口高延迟排查 Runbook

## 适用症状
网关或应用出现 HTTP 500/502/503/504、接口错误率上升、P95/P99 延迟异常或部分 API 不可用。

## 排查顺序（优先只读）
1. 按服务、路由、状态码、可用区和时间窗口聚合请求量、错误率、P95/P99。
2. 使用 request-id/trace-id 关联网关、应用和下游依赖日志，确定错误发生在哪一跳。
3. 查看线程池、连接池、队列长度、超时、重试和限流指标，识别级联放大。
4. 对比最近部署、配置、依赖版本和流量变化；检查健康检查和实例重启记录。
5. 将异常接口与正常接口、异常实例与健康实例进行对照，缩小故障范围。

## 安全边界
不要未经审批直接关闭限流、修改超时、扩大重试、切换流量或重启生产实例。重试风暴可能进一步放大下游故障。

## 恢复验证
确认 5xx 比例、P95/P99、下游错误率和告警数量恢复，并检查是否存在积压请求或延迟恢复的异步任务。
