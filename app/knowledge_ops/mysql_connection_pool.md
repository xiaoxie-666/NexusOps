# MySQL 连接池与连接超时排查 Runbook

## 适用症状
应用日志出现 `MySQL connection timeout`、`Too many connections`、连接池获取连接等待超时，或数据库请求 P95/P99 延迟升高。

## 排查顺序（优先只读）
1. 确认故障开始时间、影响服务、请求错误率和最近一次应用/数据库变更。
2. 查看应用连接池 active、idle、pending/waiting、acquire timeout 与连接创建失败指标。
3. 在数据库侧只读查看当前连接数、最大连接数、线程运行状态、慢查询和锁等待。
4. 检查是否存在长事务、连接未释放、突发流量或连接池配置与实例容量不匹配。
5. 对照故障时间窗口检查数据库实例切换、网络抖动、凭据轮换和配置发布。

## 安全边界
不要直接提高 max_connections、终止会话、重启数据库或修改生产连接池参数。此类操作必须评估实例资源、连接来源和业务影响，并由授权人员审批。

## 恢复验证
观察连接池等待数、连接超时率、数据库活跃连接和业务接口 P95/P99 是否回到基线；持续观察一个完整业务监控窗口。
