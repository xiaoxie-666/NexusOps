# CPU、内存与磁盘资源压力排查 Runbook

## 适用症状
CPU 使用率持续高位、内存耗尽、OOM kill、磁盘空间不足、I/O wait 升高或服务响应时间明显变长。

## 排查顺序（优先只读）
1. 按主机、容器、进程和时间窗口查看 CPU、RSS、working set、磁盘空间、I/O wait 和文件描述符。
2. 对比请求量、线程/协程数量、队列长度、GC、缓存和批处理任务是否同步变化。
3. 检查 OOM 事件、容器 limit/request、日志增长、临时文件和大对象/内存泄漏迹象。
4. 将资源曲线与发布、定时任务、流量峰值和依赖延迟进行关联。
5. 先定位最占资源的进程、接口或任务，不要只凭单一瞬时指标判断根因。

## 安全边界
不要未经审批直接删除日志/文件、清理数据目录、调整资源限制或杀死进程。扩容和重启也需要评估容量与副本健康。

## 恢复验证
观察资源曲线回落、OOM/磁盘告警消失、服务延迟和错误率恢复，并确认没有因清理或重启造成数据损失。
